# AGENTS.md

Agent-focused guide for the `frontend` repository. Read this first.

## Contribution workflow

Commit rules (every commit an agent authors):

- **No attribution trailers.** Never add `Signed-off-by`, `Co-authored-by`,
  `Assisted-by`, `Generated-by`, or any trailer attributing work to an AI or tool.
- **Subject:** ≤ 50 chars, capitalised, imperative mood, no trailing period
  (`Add cart badge poller`, not `Added` / `Adds`).
- **Body** (only for non-trivial changes): explain *what* and *why*, wrap at 72 chars,
  one blank line after the subject.
- **No issue references** (`Fixes #123`, `Closes #123`) in the message — put them in the PR.
- **No GitHub @-mentions** of users or teams.

Branch-then-PR:

- **Never push to `main`.** Branch first.
- Branch name: `feat|fix|chore|docs|refactor|ci/<short-desc>` (e.g. `feat/checkout-coupon`).
- Open a PR against `main`. **Squash-merge.**
- CI on PRs runs lint and build (`.github/workflows/check.yml`). Keep it green.
- **CI does not run the E2E suite** and cannot: it needs the live stack. The
  suite runs in the homelab local-stack release audit instead.

## Code quality

- **TypeScript, strict.** `noUncheckedIndexedAccess`, `verbatimModuleSyntax`,
  `erasableSyntaxOnly`. No `any` escape hatches to make a type fit.
- Function components and hooks only. One component per file for anything shared.
- **Server state lives in TanStack Query**, never mirrored into `useState`.
  Process state that is not a cached read — the checkout session — may be local.
- **Never commit secrets or tokens.** The only runtime config is `VITE_*` env vars.
- **Accessible markup**: semantic elements, labels on inputs, keyboard-reachable
  controls, and status conveyed by text as well as colour.
- **Lint clean**: `npm run lint` runs `oxlint --deny-warnings`, so a warning
  fails the build. Prefix intentionally-unused vars with `_`.
- `src/components/ui/*` is generated by shadcn — keep it pristine and customise
  at the call site. The one standing exception is documented in `badge.tsx`.

## Project overview

`frontend` is the **customer storefront SPA** for the `duynhlab` platform: browse
products, manage the cart, check out, and view orders, notifications and profile.
It is a static bundle (built by Vite, served by Nginx) that talks to the platform
**only** over HTTP through the Envoy Gateway edge.

The Backoffice for operators is a separate app (`admin-service`). This app shares
its stack by design — see homelab ADR-052.

## Build, test, lint

Node 24 (`.nvmrc`), **npm only** (`package-lock.json`; CI uses `npm ci`).

```bash
npm install        # install deps
npm run dev        # Vite dev server on :3000, hot reload
npm run build      # tsc -b && vite build → dist/
npm run preview    # serve the built bundle locally
npm run lint       # oxlint --deny-warnings
npm run test:e2e   # Playwright — REQUIRES the local stack to be running
```

- **There is no mock mode.** It was removed with RFC-0025: both the in-app mock
  store and the mock Keycloak adapter are gone. Every screen talks to the real
  services, and the E2E suite drives the real Keycloak login form.
- Before `npm run test:e2e`, bring the stack up:
  `cd ../homelab/local-stack && docker compose up -d --build`.
- First-time local setup: `npx playwright install chromium`.
- Docker: `docker build -t frontend .` then `docker run -p 80:80 frontend`.

## Conventions

**CRITICAL — Web-layer-only.** The SPA calls **only** the platform Web-layer HTTP
endpoints:

```
{VITE_API_BASE_URL}/{service}/v1/{public|private}/{resource…}
```

- `{service}` ∈ `user`, `product`, `cart`, `order`, `review`, `notification`,
  `shipping`, `checkout`. (Authentication is not a service call — it is an OIDC
  redirect to Keycloak.)
- `{audience}` is `public` (anonymous) or `private` (JWT). **Never** `internal`,
  and never `protected` — that audience belongs to the Backoffice.
- **Never** call Logic, Core, the database, gRPC, or in-cluster service DNS.
- Complex operations are server-side **aggregation endpoints** — call the
  aggregate (`/products/:id/details`, `/orders/:id/details`), do not orchestrate
  several calls client-side.
- Each `src/features/*/api.ts` owns its own `/{service}/v1/{audience}` prefix.
  `src/lib/api.ts` decides **only** the origin — no service prefixes there.
- Use the **same path the service exposes** — the edge is pass-through, no rewriting.

### Reading and writing data

- Reads go through `queryOptions` in the feature's `queries.ts`, so a key is
  defined once and invalidated by the same constant.
- Writes are `useMutation`. **Do not assume a write returns the updated
  resource** — the cart's three writes answer `{"message": "..."}`, so the page
  re-reads the cart afterwards and derives the badge from that.
- Re-reading after a write must pass `staleTime: 0`; `fetchQuery` otherwise
  honours the client default and silently returns the pre-write cache.
- Paginated lists use `placeholderData: keepPreviousData`.
- `product-service` diverges from the shared pagination contract: the request
  parameter is **`limit`**, not `page_size` (the envelope echoes `page_size`).

### Errors

`src/lib/api.ts` throws `ApiError { status, code, message, retryAfterMs, session }`
for every non-2xx, normalising both platform envelopes. Rules that are
load-bearing:

- **429 is never auto-retried** anywhere. Retrying immediately feeds the limiter.
- **503 carries `Retry-After`.** A caller may make exactly ONE paced retry with
  jitter. The checkout confirm deliberately does not: the shopper retries it.
- **Checkout's requote 409** ships the refreshed session beside the error, which
  `ApiError.session` preserves. Show the new quote first, explain after.
- User-facing copy comes from `src/lib/error-copy.ts` — never a raw backend string.

### Auth (Keycloak / OIDC — RFC-0022, RFC-0024 P3)

- Delegated to **Keycloak** (realm `duynhlab`, public client `customer-spa`,
  Authorization Code + **PKCE S256**) through the singleton in `src/lib/auth.ts`.
  Direct Access Grants are **off** and realm self-registration is **disabled**:
  there can be no in-app credential form and no register page. `/login` hands
  off to the Keycloak page.
- Tokens live **in memory inside keycloak-js**. Never persist a token to web
  storage.
- `apiFetch` awaits `auth.getToken()` before every call; a failed refresh
  redirects to Keycloak — unless the call passes `background: true` (the cart
  and bell badge polls), which fails quietly instead of yanking the user away.
- Startup: `main.tsx` awaits `initAuth()` (`onLoad: 'check-sso'` with
  `public/silent-check-sso.html`) before rendering, so guards see settled state.
- Identity comes from token claims. **`sub` is an opaque string** — never assume
  a numeric id, and compare with `String(...)` on both sides.
- Any redirect target read from the query string must pass the same-origin guard
  in `src/routes/login.tsx` (`/^\/(?![/\\])/`). Dropping it is an open redirect.
- Demo logins (seeded): `alice`, `bob`, `carol`, `david`, `eve` — all
  `password123`, by **username**, not email.

## Gotchas

- **`VITE_API_BASE_URL` and the `VITE_KEYCLOAK_*` vars are baked in at build
  time**, not read at runtime. Changing an origin requires a rebuild — there is
  no runtime config injection in the Nginx pod. `.env` holds the cloud baseline;
  `.env.development` is loaded only by `vite dev`, so it cannot leak into an image.
- **No proxying inside the pod.** Nginx serves only the SPA bundle; API calls go
  cross-origin to the gateway.
- **Availability `unknown` stays purchasable.** Inventory soft-fails to `unknown`
  when it cannot be reached, and refusing the sale on a degraded read turns a
  lost read into a lost sale. Checkout enforces stock and fails closed there.
  Never gate the buy button on a stock count — `product-service` stopped sending
  its frozen `stock` block in 1.8.0.
- **The checkout idempotency key is not cleared when a confirm fails.** Reusing
  it is what makes a retry the same order attempt rather than a second charge.
- **Asking for a checkout session when one is open returns THAT session (200).**
  Emptying the cart afterwards does not retire the quote — the funnel detects the
  divergence itself and offers a rebuild.
- **The gateway rate-limits at roughly 5 req/s.** Anything that fires one request
  per row (mark-all-as-read) must pace itself.
- Verify contrast in **both** themes. Several defects only appear in light mode.
